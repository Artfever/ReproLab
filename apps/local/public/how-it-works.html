How it works

  1. You supply inputs. A model, data, optional initial values for up to four chains, and settings such as burn-in and number of samples.
  2. ReproLab checks them. Sizes, ranges and file names are validated on this computer before anything runs.
  3. A container runs the engine. The local server starts the OpenBUGS command-line engine in a container with no network, a read-only filesystem, no extra privileges and limits on memory, processes and time.
  4. The engine log decides the state. The engine can exit normally even for an invalid model, so ReproLab reads the log and the output files to decide between succeeded, engine error and timed out.
  5. You get the record. The log, the engine output files and a run manifest with file hashes and the engine version are kept in a folder on this computer.

What ReproLab computes

The engine produces every posterior sample. ReproLab may compute labelled summaries, such as a mean and standard deviation, from the exported samples. It does not alter them.

The assistant

An optional assistant can explain documentation and a run's log. It is off unless you configure a language-model endpoint. It answers only from cited passages and declines otherwise. It cannot approve an analysis or interpret results.

ReproLab is an open-source local tool. It runs OpenBUGS in a container on this computer. A finished run is not a valid scientific finding.
