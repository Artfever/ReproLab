# ReproLab demo shot list

Companion to `script.md` (spec `03-local-product`, task 13.2, Requirements 22.1 and 22.2).

**Status: no video exists yet, and none has been uploaded anywhere.** This is a plan for a person to record. The recording must be a real screen capture of the running product. No fake footage, no mock-ups, no edited numbers. Cut only dead time.

## Pre-recording checklist

Do each item and tick it on paper. Nothing here is automated.

1. **Clean state.** Run `powershell -ExecutionPolicy Bypass -File scripts\reset-local.ps1 -DryRun`, read the list, then run it without `-DryRun`. It removes old runs and labelled containers and keeps `local-data/upstream` and `vendor/`.
2. **Docker.** Docker Desktop is running. `docker image ls reprolab-openbugs:3.2.3-vendored` shows the image. If it is missing, follow the README (browser download of the tarball, then `scripts\build-image.ps1`). Do not record the build.
3. **Start script.** Run `powershell -ExecutionPolicy Bypass -File scripts\start.ps1`. Expect `OK` lines for Node.js, Docker and the image. Open `http://127.0.0.1:8765/`.
4. **Health.** Open `http://127.0.0.1:8765/api/health` once. Expect `"ok":true,"docker":"ok","image":"present"`. Close the tab before recording.
5. **Ollama state. Decide one and write it down before recording.**
   - **Off (no `REPROLAB_LLM_*` variables set).** The assistant shows "The assistant is switched off." and a reason. Use narration version A in segment 6.
   - **On.** Set `REPROLAB_LLM_BASE_URL` and `REPROLAB_LLM_MODEL` in the terminal that starts the server (see the README, "Assistant setup"). Warm the model first: the first request took longer than the 60 s limit on a CPU-only machine. Check `http://127.0.0.1:8765/api/assistant/status` returns `enabled`. Use narration version B.
   - Never put a key in a file, and never show one on screen.
6. **Timing rehearsal.** Do the coin run once off camera and note the wall-clock time. The narration says "a couple of seconds". If your machine takes much longer, say "a few seconds" or cut the wait, and do not state a number you did not see.
7. **Example inputs.**
   - Coin and the syntax-error variant load from the Run page drop-down. No file selection is needed.
   - Seeds is optional in the video. The recording shows only the Limitations text. If the Seeds demo appears in the drop-down as "(not available)", that is fine and honest. Do not extract or show upstream files.
   - For segment 2, the field to edit is Samples. Set it to `0`.
8. **Screen hygiene.** Browser zoom 125 percent, one tab, bookmarks bar hidden. Hide the terminal, your user name, file paths, tokens and notifications.
9. **Capture.** 1080p or 720p screen capture with narration audio, saved locally. Keep the raw file.

## Fallback when the assistant is disabled

Use it when Ollama is not running, the model is not pulled, or the status call says the endpoint is unreachable. Do not fix it on camera and do not fake an answer.

1. Record the panel as it appears: the "The assistant is switched off." box and the plain-English reason.
2. Use narration version A. Say that no language model is bundled and that the assistant is off unless configured.
3. Do not type a question. The text box and Ask button are disabled in this state.
4. Do not show an answer recorded on another day as if it were live. Do not claim the assistant works in the video.
5. If you want to mention the real test, say only what `docs/evidence/local-product/assistant-real.txt` records: one real exercise with a small local model, answer quality weak, not run through the browser.

## If something goes wrong on camera

- **Coin run ends in `runner_error`.** Read the reason on the Results page. Check Docker, fix it off camera, re-record the segment. Do not edit the state badge.
- **Syntax-error run shows a different engine line than you expected.** Keep it and read what is on screen. Do not substitute a line from another run.
- **Run takes longer than planned.** Cut the waiting in editing, or keep it and trim other segments. The total must stay under 3:00.
